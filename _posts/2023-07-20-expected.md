# How to Use *std::expected*

In this tutorial, we are going to learn when to and how to use *std::expected* as well as its functions and applications.
*std::expected* was introduced in C++23. *std::expected<T, E>* offers a method to represent two values: an expected value of type T, or an unexpected value of type E.

## Motivation

Prior to C++23, we need to use *try, throw, and catch* block to make sure the values are valid.
Such as the following example shown here:

```cpp
int divide(int num, int deno)
{
    if (deno == 0)
        throw std::runtime_error("Divide by zero");
    
    return (num / deno);
}

int main()
{
    int num = 12, deno = 0;

    try {
        int result = divide(num, deno);
        std::cout << "Result: " << result << std::endl;
    } catch (const std::runtime_error& e) {
        std::cerr << "Error: " << e.what() << std::endl;
    }
}
```

This approach can be dangerous as it will cause the program to crash and cannot be handled gracefully.
In light of that, we are motivated to try out the new *std::unexpected* feature.

## Example #1: Division By Zero

Using the new feature, we can write our divide function like this:

```cpp
std::expected<int, std::string> divide(int num, int deno)
{
    if (deno == 0)
    {
        return std::unexpected("Divide by zero");
    }

    return (num / deno);
}
```

This function takes two arguments and return an expected class.
If the value of the denominator is zero, the function will return a string that entails the reason why the function call is illegal.

Let's say we call this function with 0 as the denominator:

```cpp
auto ret = divide(12, 0);

if (ret)
{
    std::println("Result: {}", ret.value());
}
else
{
    std::println("{}", ret.error());
}
```

We need to first check if the return type is true, if so, then we can safely use the result by calling *value()*. Otherwise, we know the function returns an unexpected type (in this case, it is a string). And we can inspect the error type by printing it out.

## Example #2: Division By A Multiple of Two (How to Use *and_then*)

Let say we create another function like this:

```cpp
std::expected<int, std::string> divideByPowerOfTwo(int num, int deno)
{
    if (deno == 0)
    {
        return std::unexpected("Divide by zero");
    }
    else if ((deno % 2) != 0)
    {
        return std::unexpected("Divide by a denominator that is not a multiple of 2");
    }

    return (num / deno);
}
```

In the aforementioned function, we only want the denominator to be a multiple of 2.
If the value of denominator is not a multiple of 2, then we need to return an unexpected object.

We can chain the first and the second function together by using *and_then*.
*and_then* takes a lambda function that returns *std::expected*.

An example use case is shown here:

```cpp
auto ret = divide(12, 2)
        .and_then([](int val)
        {
            return divideByPowerOfTwo(val, 3);
        });
```

We first call *divide* function and store the return value in *val*.
We then call *divideByPowerOfTwo* with the first argument as the return value of the first function call and the second argument as 3.
In this case, the value of *ret* will be an unexpected object since the second function call returns an unexpected object.
If the first function call fails, we will not even bother to call the second function as it will just return an unexpected object from the first function call.

## Example #3: How to Use *transform*

Let say we want to transfer the return value to a *std::string* by calling *std::to_string*.
In that case we need to use the *transform* keyword, like this:

```cpp
auto ret2 = divide(num, deno1)
        .transform([](int value)
        {
            return std::to_string(value);
        });
```

The reason why we need to use the *transform* keyword is because *std::to_string* we guarantee to provide a valid arguement (in this case *value* is guaranteed to be of type int) and *std::to_string* does not return an expected object.

## *and_then* vs. *transform*

In short, *and_then* takes a function that returns *std::expected* and the function may introduce another unexpected value. Whereas, *transform* takes a function that is guaranteed to return a valid output. Keep in mind that both the lambda inputs to those functions are valid since it will exit the chain if any return value of previous function calls is unexpected. 

## Summary

With the advent of *std::expected*, it is now easier to handle unexpected returns from function calls.
